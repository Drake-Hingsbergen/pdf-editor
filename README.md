# PDF Editor

A small local app for the everyday PDF jobs: open a file, fill in a form, tick
boxes, add text, sign, and save back to the same file. It runs entirely on your
own machine. Nothing is uploaded anywhere.

I built it so I could stop paying for a PDF subscription that I only used to
fill in and sign forms.

## What it does

| Task | How |
| --- | --- |
| Open a PDF | Drag it onto the window, use the Open dialog, or right-click a file and choose Open with. |
| Fill a form | Click the fields. Check boxes, radio buttons and drop-downs work. |
| Tick a printed box | Scanned forms have no real fields. The Checkmark tool places a small tick wherever you click. |
| Add text | Text tool, click where you want it, type. |
| Sign | Signature tool: draw, type or upload a signature. Up to five are remembered. |
| Save | Ctrl+S writes back into the file you opened. |
| Save a copy | The Save as button, or Ctrl+Shift+S. |

Form data stays editable after saving. Added text, ticks and signatures are
stored as standard PDF annotations, so other PDF viewers show them.

## How it is built

The PDF engine is Mozilla's open-source [pdf.js](https://github.com/mozilla/pdf.js)
(Apache-2.0), the same engine that ships in Firefox. pdf.js is not stored in
this repository. A setup script downloads one pinned release, verifies its
SHA-256 checksum and unpacks it.

Everything in this repository is a thin layer on top of the stock pdf.js viewer:

```
server.js                    Local web server, bound to 127.0.0.1 only. Serves app/ over the
                             pdf.js files and opens and saves PDFs by Windows path.
launch.js                    Starts the server if needed and opens an Edge or Chrome app window.
PDF Editor.vbs               Runs launch.js with no console window.
app/editor-config.js         pdf.js options (signature tool on, no sample file, and so on).
app/editor.mjs               Welcome drop zone, Open dialog, Save, Save as, Checkmark tool.
app/editor.css, app/images/  Styles and two toolbar icons.
tools/setup.js               Downloads pdf.js and generates app/viewer.html from the stock page.
tools/make-icon.js           Draws the app icon with no dependencies.
tools/PDFEditorLauncher.cs   Source of the small Windows launcher exe.
tools/build-launcher.cmd     Compiles the launcher with the C# compiler that ships with Windows.
tools/register-open-with.cmd Adds the app to Open with and Default apps (current user only).
tools/unregister-open-with.cmd  Removes everything the script above added.
tools/smoke-test.js          Starts the server on a spare port and checks it end to end.
tools/make-test-form.js      Optional. Generates a fillable test form (needs pdf-lib).
```

## How to deploy

Requirements: Windows 10 or 11, Node.js 18 or newer, and Edge or Chrome.

```
node tools/setup.js              download pdf.js, generate app/viewer.html
node tools/smoke-test.js         optional: 49 checks against a local server
node launch.js                   start the editor
```

To get a real Windows app with an icon that can be the default for PDF files:

```
node tools/make-icon.js
tools\build-launcher.cmd
tools\register-open-with.cmd
```

Then choose PDF Editor for `.pdf` under Settings, Apps, Default apps. Windows
does not let a program set that for you. `tools\unregister-open-with.cmd`
removes the registration again. Nothing here needs administrator rights.

There is no settings file because there is nothing environment-specific to
configure. The only runtime option is the port: set the `PDF_EDITOR_PORT`
environment variable to use something other than 4830.

## Design decisions

- **Layer on pdf.js instead of writing a PDF engine.** Rendering, form filling,
  annotation editing and saving are hard problems that pdf.js already solves
  well. My code adds the workflow around it and stays small enough to read in
  one sitting.
- **Keep pdf.js untouched.** The stock files live in `vendor/` and are never
  edited. The one page that needs changes is generated by six exact-match
  edits. If a future pdf.js release changes that markup, setup stops with a
  clear message instead of producing a broken page.
- **Save into the original file.** A browser page cannot write to a path, so
  there are two routes. Files opened through the launcher are read and written
  by the local server. Files dropped onto the window are written through the
  browser's File System Access API.
- **Safe writes.** The server writes a temporary file and swaps it over the
  original. On Windows that swap can fail for a moment while antivirus scans
  the new file, so it retries, then falls back to writing in place, and the
  page falls back to a Save as dialog if both fail.
- **Narrow server.** It listens on the loopback address only, serves only
  `.pdf` files on local drives (network paths are refused), only overwrites
  files it served earlier in that session, and rejects a save whose body is not
  a PDF. The served-earlier rule guards against mistakes. It is not a barrier
  against script running inside the editor page, which can request any PDF.
- **Only its own page may call it.** A server on the loopback address can still
  be reached by any web page open in the same browser. Every request is checked:
  the Host header must be the loopback address (127.0.0.1 or localhost), an
  Origin header must be the server itself, and a Sec-Fetch-Site header must be
  same-origin or a navigation the user started. The smoke test sends forged requests to prove
  the refusals. This gap was found in review before publishing.
- **Ticks are image stamps.** A tick typed as a text character depends on the
  viewer having the right font. A small image renders the same everywhere.
- **A real exe for Windows integration.** Explorer hides script-based entries
  from the Open with list, so the launcher is a tiny compiled program.

## Known limits

- Windows only. The server and page would run elsewhere, but the launcher and
  registry scripts are Windows specific.
- It adds to a PDF. It does not edit the text that is already on the page.
- Saving a dropped file needs a Chromium browser, and the browser asks once per
  session for permission to edit that file.
- The local server has no authentication. Web pages are refused by the header
  checks above, but another program on the same machine can send any headers it
  likes, so it could ask the server to read a PDF by path or overwrite one the
  editor has open. That program could already do the same with ordinary file
  access.
- The header checks rely on a browser that sends Origin and Sec-Fetch-Site. All
  current browsers do.
- If another program holds the PDF open with an exclusive lock, saving in place
  fails and the Save as dialog appears.
- The tick size is fixed at 11 points. Each tick can be resized by hand.
- The automated test covers the server. The page itself was tested by hand and
  with a scripted browser session, not with a committed UI test suite.
- Updating pdf.js means changing the version and checksum in `tools/setup.js`
  and confirming the six page edits still apply.
